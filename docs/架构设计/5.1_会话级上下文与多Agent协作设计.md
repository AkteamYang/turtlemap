# 会话级上下文与多 Agent 协作设计

## 1. 文档目标

本文定义多 Agent 会话中的上下文归属、上下文投影、`handoff` 与 `takeover` 的边界，并确定后续实现顺序。

当前实现将 `history` 与 `memory` 放在 `BaseAgentState` 中。这适用于单 Agent 场景，但会把同一会话拆成多份 Agent 私有历史。用户在一个会话中与多个 Agent 交互时，天然认为所有参与者都知道此前对话；Agent 私有 history 会让 Runtime 的内部实现边界变成用户可感知的上下文断层。

上下文管理迁移到会话级是多 Agent 能力的前置改造。`handoff`、`takeover` 的 Runtime 控制流在此改造完成后实现。

## 2. 核心结论

> 上下文属于会话，不属于角色。所有 Agent 都从同一份会话 Runtime 产物中构建上下文；当前 Agent、任务现场、可用工具和 token 预算只决定本轮上下文投影，不改变上下文所有权。

会话可类比为群聊：所有参与者共同写入同一条消息流。参与者切换不复制、不合并、不重置对话历史；差异只在于每位参与者在当前任务下获得的投影视图。

## 3. 状态归属

### 3.1 Session Context

`SessionState` 承接一次会话的共享上下文，至少包含：

- 按时间顺序保存的 `RuntimeArtifact` history；
- 会话级 `MemoryView`，包括中期摘要与当前运行所需的长期记忆视图；
- 输入队列、Agent 控制状态以及可恢复的任务现场索引。

会话 history 是唯一权威来源。用户输入、面向用户的 assistant 消息、工具调用、工具执行结果等产物都属于会话过程，不按 Agent 复制保存。

`MemoryView` 同样属于会话，不归属任何 Agent：

- `mid_term_memory` 承接当前会话的摘要与阶段性沉淀，直接随 SessionState 推进和持久化；
- `long_term_memory` 的权威来源可以位于用户、租户或项目级存储，但 Runtime 将本轮加载结果作为 SessionState 的会话记忆视图管理；
- 私有记忆通过会话材料的可见范围进入不同 Agent 的 projection，不在 AgentState 中复制一份 memory。

### 3.2 Agent State

`BaseAgentState` 不再承载 history 或会话摘要。它只表达当前 Agent 在本会话中的运行状态，例如：

- Agent 对应的运行期任务集合及其执行现场；
- 与 Agent 身份相关、不能由会话公共历史推导的运行期状态。

`Agent Definition`、系统提示、工具集合和能力边界属于 Agent 的静态运行时定义，不属于会话上下文，也不属于 history。

### 3.3 Task State

`ProcessingTask` 承接一次任务的执行现场，例如：

- `start_input`；
- 执行单元、工具调用关联和中断请求；
- 暂停、恢复、失败重试所需的状态。

任务不拥有独立对话 history。任务只通过自身关联信息，从会话 history 中定位本轮需要的工具过程与产物。

## 4. 上下文投影

`ContextBuildProvider` 不维护 Agent 私有 history，而是根据当前条件从 Session Context 构建投影：

```text
Session History + Session Memory
  + Current Agent Definition
  + Current Task
  + Available Tools
  + Token Budget / Context Policy
  = LLM Context Projection
```

### 4.1 公共对话语义

所有 Agent 的投影都保留会话中的用户输入与最终 assistant 消息。

因此，Agent A 完成一次回复后，Agent B 接管或 main agent 恢复时，不需要额外合并上下文。用户能看到的最终 assistant 消息已经处于统一会话 history 中，后续 Agent 能自然理解代词、追问和上下文引用。

例如，设计 Agent 回复“已将背景调整为深蓝色”后，main agent 能从同一份 history 理解用户下一句“帮我换个颜色试试”。

### 4.2 工具过程投影

工具调用与工具结果同样属于会话 Runtime 产物，但不等于每个 Agent 都应在 LLM 上下文中看到完整工具过程。

- 当前 Agent 自己的历史以原生 `assistant`、`tool` 消息协议投影。工具已不可用且结果仍有效时，折叠中间工具过程，只保留本轮输入与最终 assistant 结论；工具已不可用且存在过期结果时，排除整轮，避免原生 history 出现当前无法调用的工具。
- 工具仍可用但结果过期时，保留原生轮次和工具调用协议，在 `tool` 消息中标记结果已过期并移除原始结果正文。本轮结论只表达当时状态，不作为当前事实依据。
- 其他 Agent 的连续历史作为 `Group Input` 放入接收 Agent 最近用户输入的 `Task Context`。`Group Input` 使用 XML 表达 `message`、`tool_call` 和 `tool_result`，不构成当前 Agent 的原生工具调用协议，因此不按当前工具集合折叠或排除。
- `Group Input` 中过期的 tool result 同样移除原始结果正文，并在对应 `<tool_result>` 中标记过期；同轮其他用户输入与 assistant 结论保持可见，保留跨 Agent 会话语义。
- 工具原始数据不作为跨 Agent 共享的当前事实。需要跨 Agent 延续的事实，应由最终 assistant 消息表达，或由业务系统作为权威事实源保存。

这里的裁剪是上下文构建策略，不是 Agent 对会话 history 的访问权限隔离。

#### 4.2.1 Group Input XML 格式

`Group Input` 表示当前 Agent 自上次执行以来，其他参与者在会话中产生的连续信息。它只出现在接收 Agent 最近一条用户输入的 `Task Context` 中，不单独生成 `user` role，也不替代原始会话 history。

渲染结果使用一个 `<group_input>` 容器，容器前保留简短说明。容器内部按原始会话顺序排列以下元素：

```xml
<group_input>
  <message actor="User">
    用户输入内容
  </message>
  <message actor="research_agent">
    其他 Agent 的回复内容
  </message>
  <tool_call actor="research_agent" name="query_metrics" id="call:metrics">
    {"metric":"latency"}
  </tool_call>
  <tool_result call_id="call:metrics">
    工具结果内容或过期标记
  </tool_result>
</group_input>
```

元素与属性语义如下：

- `<message>` 表示普通会话消息。`actor="User"` 表示用户消息；其他值为产出该消息的 Agent 稳定名称。
- `<tool_call>` 表示其他 Agent 已经发起的工具调用。`actor` 为调用 Agent，`name` 为工具名称，`id` 为调用标识，正文为原始参数文本。
- `<tool_result>` 表示工具调用结果。`call_id` 与对应 `<tool_call>` 的 `id` 关联，正文为结果的标准投影文本。
- 元素正文与属性值按 XML 文本规则转义，防止历史内容改变容器结构。
- `<tool_call>` 只用于描述外部会话过程，不是当前 Agent 的原生 tool call；当前 Agent 只能调用本轮工具集合中提供的工具。
- 结果过期时，`<tool_result>` 保留调用关联和过期标记，不保留原始结果正文；同轮其余元素继续按原顺序保留。

多个连续外部 Agent 分组在进入同一接收 Agent 前合并进同一个 `<group_input>` 容器，避免模型将其理解为多次独立用户输入。

### 4.3 压缩与记忆

会话摘要、历史裁剪和 token 预算均以 Session Context 为对象：

- 中期摘要覆盖整条会话，而不是某一个 Agent 的局部 history；
- 压缩结果合并回 SessionState；
- Agent 切换不会产生新的摘要副本；
- 不同 Agent 因工具、任务和 token 预算形成不同投影，但共享同一份摘要与原始 history。

现有压缩算法不需要因上下文归属调整而重写。可压缩轮次选择、摘要生成、保留最近轮次、历史边界校验和 `ContextCompressionResult` 合并语义继续保持；改造只将压缩源和合并目标从 `owner_agent_state` 切换到 `session_state`。

后台压缩任务的并发键随之收敛为 `session_id`。同一会话只维护一项运行中的会话摘要任务，避免不同 Agent 对同一份 history 并发生成不同摘要。

私有材料进入摘要前必须先按可见范围分组。公共摘要不得吸收 Agent 私有记忆、任务私有工具结果或未授权材料；相同可见范围的材料才允许互相合并。

## 5. 多 Agent 控制语义

### 5.1 Handoff

`handoff` 表示对一项明确任务的临时委派。当前已实现的控制权转移、原始输入重入队、`Group Input` 投影、继续标记与自动返回语义，以[Handoff 控制权转移设计](./Handoff控制权转移设计.md)为准。

1. 当前 Agent 将任务交给目标 Agent；
2. 目标 Agent 使用同一份会话上下文，并叠加自己的 Agent Definition、任务现场和工具视图；
3. 任务进入 complete 后，Runtime 检查该任务最后一个不含 tool call 的 LLM 结果；
4. 最终内容不含 `<#CONTINUE#>` 时，Runtime 自动切回直接父 Agent；
5. 最终内容包含 `<#CONTINUE#>` 时，handoff 保持有效，目标 Agent 保持当前 Agent 并等待下一次输入。

`handoff` 不复制 history，也不执行 Agent history 合并。目标 Agent 的最终 assistant 消息已经写入 Session Context；Runtime 只处理当前 Agent 的返回切换。

### 5.2 Takeover

`takeover` 表示显式的当前 Agent 切换：

```text
current_agent = target_agent
```

它与任务创建、任务完成、任务暂停、会话结束标记均无关。切换后的当前 Agent 持续生效，直到下一次显式 `takeover` 切到另一个 Agent 或切回 main agent。

`takeover` 不创建 handoff 任务，也不要求目标 Agent 通过 `<#CONTINUE#>` 决定是否保留会话主导权。

## 6. 改造顺序

### 第一阶段：会话级上下文迁移

1. 将 `BaseAgentState.history` 迁移到 `BaseSessionState`；
2. 将 `MemoryView` 整体迁移到 `BaseSessionState`，包括中期摘要与长期记忆运行视图；
3. 调整 checkpoint、状态序列化、MySQL 示例和内存存储，使会话 history 与摘要只保存一份；
4. 调整 `ContextBuildInput`，从 SessionState 读取 history 与会话记忆，Owner AgentState 只提供任务与 Agent 运行状态；
5. 调整压缩逻辑，使压缩输入、合并目标和后台压缩回写均指向 SessionState，并按 `session_id` 防止重复调度。

### 第二阶段：会话投影治理

1. 将 history 分轮、工具结果有效性、工具可用性、工具过程折叠统一收敛到 Session Context 投影；
2. 以当前 task 与 owner agent 为条件决定工具过程是否进入投影；
3. 覆盖 main agent、任务 owner、切换 Agent 的上下文构建测试；
4. 验证同一会话中 Agent 切换后，用户与最终 assistant 对话语义连续，工具中间过程不泄漏。

### 第三阶段：多 Agent 控制流

1. [已完成] 在 Runtime 中实现 `handoff` 的任务委派与基于 `<#CONTINUE#>` 的返回判断；
2. [待实现] 实现与任务无关的显式 `takeover`；
3. [进行中] 为 handoff、takeover、暂停恢复、工具过程裁剪组合场景补充状态流转测试；
4. [进行中] 更新 Runtime、Kernel 数据结构与状态持久化设计文档中的旧 handoff 语义。

## 7. 约束

- 不为每个 Agent 保存独立 history、副本摘要或独立会话压缩结果；
- 不在 handoff 返回时复制或合并 Agent history；
- 不把工具原始结果当作跨 Agent 的长期会话事实；
- 不用任务状态隐式执行 `takeover` 或取消 `takeover`；
- 不让 Agent 切换改变用户已经看到的会话消息顺序。

## 8. 完成标准

完成第一阶段后，同一 Session 中任意 Agent 构建上下文时都从同一份 history 与会话摘要出发；AgentState 中不再保存会话 history 和会话中期摘要。

完成第三阶段后，`handoff` 与 `takeover` 能在不复制会话上下文的前提下切换当前 Agent，并保持用户可见会话语义连续。
